# Experience Design and User Journeys

## Product promise
Find your kind of night. User intent: **who**, **when**, **where**, **mood**, **music**, **budget**, **constraints**. Offer conversational input and accessible structured filters; neither should require a long questionnaire.

## Main journeys
A. First-time visitor: choose market → enter intent → shortlist 3–5 matches → understand why/unknowns → venue detail → external booking handoff.
B. Returning visitor: saved preferences and market switching → date-specific suggestions → reminders only with opt-in.
C. Group: create shareable shortlist, allow invitees to express preferences without exposing private profile data, rank compromises; defer full group voting beyond MVP if needed.
D. Operator: claim venue → prove authority → submit changes/events → see review state.
E. Reviewer: see conflicting claim and source evidence → approve/reject → audit record.

## Essential screens
Landing and market selector; discovery with date/time and budget; result cards with verified/uncertain labels; venue profile and event occurrences; favorites; admin review; market setup; operator claim/update (later pilot phase).

## Ranking contract
Hard filters: geography, date/time, budget ceiling if known, admission restrictions, accessibility needs and user-specified must-haves. Soft signals: genre, energy, conversation comfort, seating, cuisine, popularity, preference similarity. Unknown hard-constraint data must not silently count as a pass; either exclude or present as 'needs confirmation' under explicit user control. Explanation must reference stored claims, not generative invention.

## Design constraints
Mobile-first responsive; WCAG-aligned accessibility; keyboard navigation; RTL Arabic; clear price currency/basis; distinguish scheduled vs confirmed live performance; avoid fabricated availability or event details. No autoplay sound.
