Goal: replace the intent form with a chat-plus-refine discovery input and widen the typed query, using only synthetic data. The model parses intent and nothing else (ADR-004). Eligibility, ranking and explanations stay deterministic. No market, currency, timezone or locale literals in shared logic (ADR-009).

Requirements, as ruled by the product owner:

1. When. Replace the required date and from/to with a `when` object: exact date, date range, or relative window ("tonight", "this weekend", "next 3 days"), plus an optional time-of-day band (brunch, afternoon, evening, late night, evening by default). Cap the window at 14 days. Evaluate eligibility per day, return each venue once on its best day with the other matching days listed, and carry the matched date on the result. Resolve relative phrases in the market timezone from the request clock.

2. Party size and budget are optional. Remove the party default of 4 and the budget placeholder. No budget means price is shown and never filtered. No party size means group fit is not scored.

3. Experiences replace genres. Add a controlled experience vocabulary as a seeded table, global with per-market extensions (doc 10). Propose a v1 list of about 20 tags and stop for approval before seeding. Users type freely; the parser maps words onto the vocabulary and the UI shows the mapping as editable chips. Results carry a deterministic match strength: overlap between the chosen tags and the venue's stored tags, weighted by evidence state. Never display model confidence and never label match strength "confidence".

4. Age. Add "who's coming" age bands (kids, teens, adults only, seniors). Minimum admission age is a hard filter and needs a tri-state `minimumAge` venue attribute. Age suitability tags are a soft signal. Never collect or store the user's own age. The selection lives in the URL only.

5. Noise level. Rename "Conversation level" to "Noise level" with four bands (Quiet, Moderate, Lively, Loud) plus no preference, mapped onto noiseBand and conversationFriendliness as a soft preference.

6. Must-haves. Remove "quiet enough to talk". Implement these as tri-state hard filters (ADR-011): outdoor seating, indoor seating, wheelchair accessible, kids welcome, licensed venue, alcohol-free venue, halal, takes reservations, open past midnight, live performance confirmed. Each needs a stored attribute with evidence, so extend the schema, fixtures and seed. Show the "needs confirmation" count beside each must-have.

7. Outing type. Add a global taxonomy (Restaurant, Drinks and lounge, Café, Live music, Concert or show, Nightlife, Outdoor activity, Culture, Family activity, Wellness, Sports and active, Beach or day out) as a venue kind with per-market extensions. Activity providers are venues with sessions as occurrences; no new entity. Fixtures populate only Restaurant, Drinks and lounge, Live music, and Concert or show.

8. Chat plus Refine. One screen, mobile first: chat input ("Describe your night"), chips showing what was understood, a collapsible "Refine your search" panel grouping When, Who, Budget, Outing type, Experiences, Noise level and Must-haves, then results. Chat and Refine edit the same typed query and the query is the URL. Chat turns patch the query ("cheaper", "outdoor instead", "Saturday then"). One clarifying question at most, only when a hard filter is missing. Chat scope is intent capture and refinement; a question about a venue is answered from stored claims through the existing deterministic explanations, or with "we don't know that yet". Build the IntentParser port with the mock adapter only: deterministic rules, offline, English and Arabic, used in tests and whenever no key exists. Do not add an LLM provider, SDK or key. That is a separate approval.
